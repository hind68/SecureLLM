# Database

PostgreSQL is provided by Docker Compose for local development.

The first Flyway migrations create the LLM provider catalog:

- `fournisseur_llm`
- `modele_llm`

Additional migrations add the persistent conversation model:

- `utilisateur`
- `conversation`
- `message`

`V3` adds `modele_llm.nom_affichage` without changing the already applied `V1` and `V2` migrations. `V4` creates a reproducible `demo-user` for local development only. `V5` adds `message.modele_llm_id` so each assistant response keeps the model that actually generated it, even when the conversation current model later changes.

The conversation `modele_llm_id` is the current model used for the next response. History filtering by model includes conversations whose current model matches the filter, and conversations containing at least one assistant message generated by that model.

The demo user is temporary and should be replaced by the authenticated JWT user in a later security phase.
The Spring Boot backend connects to PostgreSQL on `localhost:5433` when it runs on the host machine. Flyway runs automatically on backend startup.
